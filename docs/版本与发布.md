# W1H 版本、环境与发布

本文是产品版本、DSH 基线、组件版本和运行环境的维护位置。源码身份以 apps/desktop/w1-product.json 为准，发布结果以 GitHub Releases 的资产与验证记录为准。

## 两条版本线

W1H 版本独立递增，例如 0.1.0-alpha.4；DSH 基线记录已整合的标签，例如 dsh-v0.2.1-rc.2。W1H 可以在同一个 DSH 基线上多次发布。发现 DSH 新版不表示 W1H 已整合，也不表示用户已有可安装更新。

Windows 托盘提供「检查 W1H 更新」「DSH 上游更新」和「关于」。设置旁的更新状态对应 W1H；DSH 通过独立通知和入口提供发布说明、基线对比及开发任务。「关于」同时显示 W1H 版本、DSH 基线、运行方式与构建信息。内部 @deepseek-ai 包版本用于依赖兼容，不作为 W1H 用户版本。

## 日用、测试与安装版

| 环境 | 应用与数据 | 更新方式 |
| --- | --- | --- |
| 日用源码版 | 保留现有入口；.w1-harness 与 AppData/W1 Harness | 局部构建暂存，正常退出重开后应用；产品更新入口不改源码。 |
| 独立候选工作区 | Git worktree；独立依赖和产物 | 在候选目录检查和打包，不覆盖日用产物。 |
| 测试版 | W1_TEST_MODE=1；W1 Harness Test；.w1-harness-test 与 AppData/W1 Harness Test | 用 scripts/w1/Start-W1Test.ps1 启动，更新入口只查看发行信息；由候选工作区更新程序。 |
| 安装发行版 | 独立 W1 安装目录，默认沿用正式 W1 数据目录 | 从 W1 GitHub Releases 下载校验，再确认任务停止与重启安装。 |

日用源码版与普通安装版使用同一份正式数据，因此只运行一个正式实例。测试模式具有独立身份和数据，可与日用版并存；不复制聊天、项目、浏览器登录态、远程绑定或第三方插件，也不注册正式版协议与快捷方式，不执行正式版安装器。原版 DSH 继续独立。

scripts/w1/prepare-test-profile.mjs 建立测试配置。显式使用 --copy-official-api 才复制日用存储里的 DEEPSEEK_API_KEY 引用；目标凭据文件只保留这一条，已有目标先备份，只输出复制与验证状态。公开仓库和发行包不含真实 Key。没有本机官方凭据时，应在测试应用设置中配置自己的 Key。

## 用 W1 开发 W1

日用实例负责编辑、提交与发起候选构建；独立工作区负责产物；测试实例负责验证。通过后再合入日用源码。正在执行开发任务的实例不通过构建覆盖自身。

升级前记录分支、提交、检查结果和下一步。聊天恢复不表示被中断的工具进程续跑。程序回退和数据恢复分别处理；含新必需事件或格式迁移的数据不保证能被旧程序读取。源码、旧发行资产和数据备份分别保留。

## 产品更新与频道

W1H 更新源为 Wh1te0ne/W1-Harness 的 GitHub Releases，使用 v<W1版本> 标签；DSH 标签不参与二进制版本比较。alpha、beta 和正式频道从 W1 版本选择；正式版不接收预发布，beta 不回到 alpha，禁止降级。

安装版定期检查，由用户发起下载，并另行确认安装。检查失败显示失败，不冒充最新版。electron-updater 校验文件哈希；当前预览包未使用 Windows Authenticode 签名，哈希校验不等于证书验证。安装前检查活动任务、锁定新任务入口并等待 Host 安全退出，准备失败会恢复工作区。

源码 ZIP 不等于安装包。桌面更新必须包含频道 YAML、Windows EXE 和更新文件；Chrome、中继或源码单独发布不能成为桌面更新。源码版只提供发行信息与下载入口，其 Git 工作区继续采用开发流程。
