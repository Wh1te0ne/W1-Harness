# W1H 版本、环境与发布

本文是产品版本、DSH 基线、组件版本和运行环境的维护位置。源码身份以 apps/desktop/w1-product.json 为准，发布结果以 GitHub Releases 的资产与验证记录为准。

当前公开发行为 [W1H 0.2.0](https://github.com/Wh1te0ne/W1-Harness/releases/tag/v0.2.0)，集成 DSH dsh-v0.2.1-rc.2。Windows x64 安装包、更新文件和配套组件共 11 项资产已公开，远端大小和 SHA256 均与本地一致；包内运行检查及旧 alpha 客户端公开下载校验已通过。实际安装/升级重启及设备验收状态见[工作记录](工作记录.md)。

## 数字版本规则（2026-10-22）

W1H 使用三段式版本号“主版本.次版本.修订号”，新的公开发行不再附加 alpha、beta。此次功能汇总定为 **0.2.0**；后续小修复递增为 0.2.1、0.2.2，成批功能更新递增为 0.3.0。1.0.0 留给明确的兼容性与维护范围，不按修改数量自动升级。

本地快速迭代以提交与构建标识区分，只在准备公开交付时递增产品版本。同一份验收源码用于 Windows 构建和 GitHub 标签；每次发行保留源码、安装包、版本说明、组件清单和 SHA256，既有发行资产不覆盖。

| 版本 | 范围 | 交付条件 |
| --- | --- | --- |
| 0.2.0 | 计费与价格来源、主题持久化、会话交互、更新恢复及配套组件 | 源码检查、完整构建、包内运行检查、旧数据迁移与更新渠道验证 |
| 0.2.x | 已发布功能的修复与兼容维护 | 相关回归通过，发布新安装包与修复说明 |
| 0.3.0 | 下一批明确的功能更新 | 按实际需求确定范围，不提前承诺未排期功能 |

0.2.0 的功能与迁移限制见根 [CHANGELOG](../CHANGELOG.md)。配套版本分别为 Chrome 0.2.6、Android 0.1.1、中继 0.1.1。Chrome 0.2.5 已有本地交付，新截图回退修复使用新版本；未重复覆盖旧目录。手机真机、真实 Chrome 交互与 Windows 签名状态在发行说明中单独标注。

## 两条版本线

2026-11-04 核验：W1H 最新公开发行仍为 0.2.0。DSH 0.2.2-alpha.3 已完成 W1 兼容整合，并从原 W1 启动器在正式目录实际运行；用户确认原会话可打开并发送消息。独立 Test 开发模式已退役。取舍、插件和验证范围见[Alpha.3 整合](上游同步-0.2.2-alpha.3.md)。

W1H 版本独立递增，例如 0.2.0；DSH 基线记录已整合的标签，例如 dsh-v0.2.1-rc.2。W1H 可以在同一个 DSH 基线上多次发布。发现 DSH 新版不表示 W1H 已整合，也不表示用户已有可安装更新。

Windows 托盘提供「检查 W1H 更新」「DSH 上游更新」和「关于」。设置旁的更新状态对应 W1H；DSH 通过独立通知和入口提供发布说明、基线对比及开发任务。「关于」同时显示 W1H 版本、DSH 基线、运行方式与构建信息。内部 @deepseek-ai 包版本用于依赖兼容，不作为 W1H 用户版本。

2026-11-04 起使用单一 W1 工作区：修改与相关检查、准备更新、完全退出重开后生效；不再要求独立 Test 或跨工作区推广。依赖和运行时替换前必须退出 W1，GitHub 发布另行授权。具体操作以[开发流程](开发与上游维护.md#w1-self-development)为准。

临时验包环境不是长期开发入口，也不构成额外 W1H 产品版本。

## 产品更新与频道

W1H 更新源为 Wh1te0ne/W1-Harness 的 GitHub Releases，使用 v<W1版本> 标签；DSH 标签不参与二进制版本比较。新发行使用 latest 频道。0.2.0 同时提供内容相同的 latest.yml、alpha.yml 和 beta.yml，使既有预发布安装版可以升级；升级后继续读取 latest，禁止降级。历史标签保持原样。

安装版定期检查，由用户发起下载，并另行确认安装。检查失败显示失败，不冒充最新版。electron-updater 校验文件哈希；当前 Windows 包未使用 Authenticode 签名，哈希校验不等于证书验证。安装前检查活动任务、锁定新任务入口并等待 Host 安全退出，准备失败会恢复工作区。

源码 ZIP 不等于安装包。桌面更新必须包含频道 YAML、Windows EXE 和更新文件；Chrome、中继或源码单独发布不能成为桌面更新。源码版只提供发行信息与下载入口，其 Git 工作区继续采用开发流程。
