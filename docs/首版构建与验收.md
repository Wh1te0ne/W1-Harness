## 产品身份与隔离

版本及上游基线的唯一配置为 [w1-product.json](../apps/desktop/w1-product.json)。应用与安装器版本为 W1 自有版本；内部 DSH 包保留上游版本及包名，用于依赖和插件兼容判断。

| 项目 | W1 设置 |
|---|---|
| 名称 | W1 Harness |
| 应用标识 | local.w1.harness |
| 安装包内 package name | w1-harness |
| 系统 URL 协议 | w1-harness://open |
| 用户数据 | %APPDATA%\W1 Harness |
| Harness 数据、会话与插件根 | %USERPROFILE%\.w1-harness |
| 首次默认工作区父目录 | %USERPROFILE%\.w1-harness\projects |
| 上游检查记录 | %APPDATA%\W1 Harness\upstream-releases.json |

打包应用在获取单实例锁、启动 Host 前设置 W1 数据路径，不继承其他进程的 DSH_HOME。开发实例通过显式 W1_HOME 与 W1_USER_DATA 使用项目内测试目录；[隔离启动脚本](../scripts/w1/Start-W1Baseline.ps1)设置了独立调试端口。正式启动不需要调试端口。

安装器和卸载器通过 W1 应用标识、包名和实际安装路径定位自身。上游应用二进制更新器与强制更新策略均停用，W1 不加载官方发布、签名或强制更新配置。桌面菜单不提供会写入系统 dsh 命令注册的入口。原 DSH 的目录、协议、账号、会话及插件保留在原位置。

## 上游检查与人工跟进

每次应用启动后都会异步查询上游；持续运行期间每日检查，系统恢复时按上次成功检查时间进行 24 小时节流。启动和手动刷新不受该缓存限制。用户可从“应用 → 检查 DSH 上游更新…”手动刷新。有待跟进版本时，设置按钮旁保留“上游待跟进”入口。

检查器读取官方 GitHub releases 列表，区分源码发布与本地 W1 安装版本，覆盖预发布和正式发布。同一标签只发一次自动提醒；查看、稍后跟进、复制开发任务均不会把它标成已整合。新 W1 构建明确更新 w1-product.json 的 upstreamTag 与 upstreamPublishedAt，才代表开发基线推进。

网络失败或 GitHub 限流会显示检查未完成，保留上次成功时间与待跟进结果，不冒充“没有更新”。读取损坏的本地提醒记录时保留原文件并显示错误；检查该文件后重启应用恢复检查。发布说明作为纯文本资料呈现，链接固定在官方仓库。

“复制升级任务”包含 W1 版本、当前基线、目标标签、比较和发布说明链接、保留定制功能与双开验证要求。用户将它粘贴到开发聊天后再开展工作；应用不会自动发送消息、合并 Git 或安装程序。

## 构建与开发运行

使用项目锁定的 Node、pnpm 与依赖。工作区 pnpm store 固定在 .work/pnpm-store。Windows 内测使用未签名模式，不读取官方签名配置，也不上传产物。

```powershell
node .work/tools/pnpm-11.28.5/package/bin/pnpm.cjs run package:desktop:win:x64:unsigned
```

主流程先运行完整构建，再打包内部依赖、准备 Electron 与 Node/Python/Office 运行时，最后生成 NSIS 安装包并执行打包后运行时检查。生成目录为 apps/desktop/.desktop-build/targets/win-x64/unsigned-artifacts，验收后将安装包与校验信息复制到不可变 releases/<W1版本>/。

已经构建的开发实例可使用：

```powershell
& ./scripts/w1/Start-W1Baseline.ps1
```

开发 Electron 的 app.getVersion() 仍来自上游工作区清单；W1 界面、关于页和最终安装包采用独立 W1 版本。不要把开发实例版本号当成安装包元数据。
