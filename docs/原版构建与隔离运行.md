## 基线与工具

源码标签为 `dsh-v0.2.1-alpha.4`，分支为 `codex/w1-baseline`。独立 `.git` 不是浅克隆，保留基线可达的 22,346 个提交。`upstream` 指向官方仓库；未创建自有远程 origin。W1 说明、忽略规则、翻译排除清单和启动脚本为本地工作区改动，尚未创建下游提交。

本轮使用 Node 24.14.0、pnpm 11.28.5、Electron 44.7.0。pnpm 引导包位于 `.work/tools/pnpm-11.28.5/`，已核对 npm 完整性值；依赖安装使用冻结锁文件，store 位于 `.work/pnpm-store/`，未修改全局 pnpm。

## 隔离方式

| 项目 | 位置或行为 |
|---|---|
| DSH 数据根 | .work/runtime/dsh-home |
| Electron 用户数据 | .work/runtime/electron-user-data，已从运行进程核对 |
| 首次默认项目 | .work/runtime/documents/deepseek-harness，覆盖系统 Documents 的默认位置 |
| 开发运行时 | apps/desktop/.desktop-build/，由官方开发入口准备 |
| Host 服务 | 上游请求操作系统分配端口 0，仅监听 127.0.0.1；本次分配为 10488，每次可能不同 |
| 调试端口 | 默认 19320/19321/19322，启动前检查占用，可传 DebugPortBase |
| 更新与协议 | 未打包开发实例；不注册系统 dsh 协议；上游打包更新器不启用 |

启动脚本只设置自身进程及子进程环境，不更改系统变量。未复制官方用户目录。测试 home 中的隔离补丁若与预期不同，脚本会停止，不覆盖已有内容。

## 复现入口

以下构建使用本轮实际执行的固定版本入口。在项目根目录的 PowerShell 7 中运行：

```powershell
$env:DSH_GATE_CONCURRENCY = '2'
$env:RAYON_NUM_THREADS = '4'
node '.work\tools\pnpm-11.28.5\package\bin\pnpm.cjs' run build
```

已构建后，运行本轮验证过的隔离启动入口：

```powershell
& '.\scripts\w1\Start-W1Baseline.ps1'
```

脚本调用上游 `pnpm run start:desktop`。默认端口被占用时会停止，可以显式选择另一组 DebugPortBase。首次或再次启动仍会执行上游运行时准备和自检，可能需要等待。欢迎页可选择“添加 API Key → 稍后配置”，无须为了启动验收填写真实账号信息。正常退出使用应用菜单的退出命令；关闭窗口可能仅隐藏到托盘。

## 证据与已知问题

- `.work/logs/build.log`、`build-result.json`：完整构建。
- `.work/logs/install.log`、`primary-runtime.log`、`primary-runtime-result.json`：依赖和运行时。
- `.work/logs/desktop-start.log`、`desktop-start-retry.log`：首次失败及修正后的启动。
- `.work/ui-verification/workspace.png`、`settings-models.png`、`welcome.png`：实际 Electron 渲染器截图，不是模拟网页。
- `.work/ui-verification/native-process.json`、`isolation-result.json`：进程内路径与退出后对照。
- `.work/logs/lint.log`、`lint-result.json`、`docs-check.log`：静态和文档检查。

首次 W1 启动脚本用 .NET API 清理环境变量时，当前 PowerShell 把空值写成了空字符串，Electron 因而误进 Node 模式。已改用 Remove-Item 删除进程环境变量，修正后的实际原生启动通过，未改上游应用代码。

上游 `verify-repository-references` 把 `python/sdk/uv.lock` 中一个 PyPI wheel URL 的散列片段识别为 commit-hash；该文件和检查器均与标签相同，未为规避检查修改依赖锁。文档检查没有全部通过，因此没有宣称整仓所有检查为绿，也未继续重复运行包含该失败项的完整 doc-sync。

启动主进程日志另有一次 mandatory-status 处理器尚未注册的报错，以及开发模式 CSP 警告；它们没有阻止此次工作区和设置加载。Playwright 接入后的主界面记录为 0 个 renderer error。首次欢迎页受 Electron 遮挡状态影响，自动化采用确认过的按钮定位直接点击；进入主界面后的菜单和设置使用普通点击。

真实模型调用、浏览器操控后端、安装器、签名、账号迁移及现有插件接入均未验证。下一步先确定首项 W1 功能，再在独立分支实施。
