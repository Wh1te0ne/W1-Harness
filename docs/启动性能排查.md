# W1 启动性能排查

最近核验：2026-10-21，Windows 本机。结论来自日用历史日志、独立配置的无窗口启动和 CPU 采样；当日后续文件访问定位见本文末节。本文排查没有重启或替换日用／Test，没有推广性能候选，也没有修改其他任务的更新队列。

## 已确认的现象

2026-10-20 23:26 的日用启动在 109.476 秒记录 workspace-shown，其中 host-profile-start 到 host-profile-ready 为 91.840 秒，随后浏览器服务初始化为 5.982 秒。旧日志没有逐插件计时，不能事后把这 91.840 秒精确归因到某个插件。此前同阶段曾为 9.097 秒，存在明显波动。

为继续定位，在 `.work/self-dev` 的 app-boot 增加可开关的逐插件计时。诊断启动环境使用 `DSH_STARTUP_TRACE=1`；普通启动不安装观察器。输出为 `[dsh-startup-plugin]` JSON：

- `import`：配置模块导入的墙钟耗时，含共享依赖及事件循环争用。
- `activate`：插件实际进入加载后，到激活或失败的耗时；`waitMs` 单列等待依赖的时间。
- `pending`：配置树结算后仍未激活的条目，可能是未满足的可选依赖，不能一律当成故障。
- `complete`：诊断区间结束及结果。观察器和临时方法包装随后移除。

记录不输出配置值、错误正文、聊天、凭据或本地模块路径。各插件并行加载，父 Include 还包含子树，因此不能相加或将最长导入项当成独占 CPU 热点。计时区间从 Loader 和宿主准备完成后开始，不覆盖此前的 profile 解析和桌面外壳初始化。

测试通过正式 `dsh` profile 启动 `dsh-base` 与 `dsh-web-app`，使用空白测试 home、独立 XDG 目录和随机本地端口；不复制日用聊天、插件数据或凭据，不打开浏览器和桌面窗口，应用就绪后自动退出。这覆盖与桌面共用的基础插件树，不覆盖日用数据量以及 Electron、浏览器、远程和 Office 后置初始化。

## 候选优化与对照结果

1. 目录规范化复用现有 `realModuleDirectory`：普通 Node 使用原生 realpath；pkg 虚拟文件系统保持原有适配。
