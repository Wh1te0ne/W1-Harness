# W1H 发布操作

本页维护 Windows x64 发布步骤。版本与环境定义见[版本与发布](版本与发布.md)。不读取官方 DSH 的签名凭据，也不上传到官方更新源。

## 准备和构建

先提交有效源码，再在独立 worktree 安装锁定依赖，运行针对性回归与完整构建。使用 PowerShell 7 和锁定的 pnpm。不要在正在运行的日用工作区执行完整构建、清理或安装循环。

W1 Windows 打包入口为 node scripts/w1/package-release.mjs。它复用既有完整运行时打包流程，配置 W1 的 GitHub 更新源，生成未签名安装器，并执行打包运行时检查。官方打包/发布工作流保留供上游维护参考，W1 发布不依赖 DSH 的专用 runner、COS 账号或签名硬件。

apps/desktop/.desktop-build/targets/win-x64/unsigned-artifacts 保存构建结果。正式对外目录为 releases/<W1版本>，同版本目录不可覆盖。核对 EXE 的产品版本、Git 提交和 app-update.yml 中的仓库；不能只检查文件名。

仅修改桌面壳时，可以在核对运行时来源、确认 CLI、Host、插件与 Client 源码均未改变后，复用已通过完整校验的运行时，单独重建桌面并重新打包、执行完整包内检查。组件清单分别记录本次桌面来源和运行时来源；W1_RUNTIME_SOURCE_COMMIT 仅用于填写核实后的运行时提交，不代替完整性校验。普通发布工作流仍从完整构建开始。

## 资产和发布

收集 Windows EXE、blockmap 和对应频道 YAML，按需附带 Chrome ZIP、Android APK、中继部署 ZIP、组件清单及 SHA256SUMS。运行 scripts/w1/collect-release.mjs 收集时，会先校验频道描述中的 SHA512、尺寸与安装器字节相符，目标目录必须不存在。

使用 v<W1版本> 标签创建 GitHub 草稿发行，上传并核对所有资产后再发布。新版本使用普通 vX.Y.Z 标签与 latest 频道，不标为 prerelease；历史预发布标签不改名。数字版收集器同时写入 alpha/beta 兼容描述，并只提取该版本的 CHANGELOG 段落。Android 与中继版本从各自源码声明读取，不固定旧 APK 文件名。发布说明包含 DSH 基线、各组件版本、变更、验证、数据兼容及回退限制。

GitHub Actions 的 W1 Windows release 工作流默认只构建和保留资产；手动勾选 publish 才由独立发布任务核对 SHA256 和源提交并创建新发行。构建任务只有读取权限，发布任务使用 GitHub 临时令牌；既有同版本不覆盖。新增签名能力时使用独立 W1 凭据。公开仓库不得携带私钥、API Key、配对码、绑定、聊天、生产存储或浏览器登录数据。

## 验证和回退

构建后分别核对源代码检查、包内运行时、更新源、下载校验、安装和真实桌面功能。测试版设置 W1_TEST_MODE=1，使用 scripts/w1/Start-W1Test.ps1 -Executable <测试程序路径>，不接管日用数据或快捷方式。

更新验证需要两个不同产品版本，确认低版本读取真实更新源，下载目标资产，拒绝校验错误，确认任务处理后安装重启。仅测试状态机不表示完成安装更新验收。发布失败时保留草稿及诊断，修正后用新版本；不替换已经交付的同版本资产。

程序回退使用保留的旧安装器；数据需要按对应升级说明恢复。上线前、验证后和交接时更新[工作记录](工作记录.md)，明确尚待用户原生验收的部分。
