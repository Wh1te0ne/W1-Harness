# DSH 0.2.2-alpha.3 整合

本页维护 2026-11-04 发起的 W1 下游整合。目标为上游标签 `dsh-v0.2.2-alpha.3`，不是追随变化中的 master；W1H 公开发行仍为 0.2.0。本机日用仍运行 RC.2 基线，本轮 Alpha 在独立源码 Test 内验证，尚未推广日用或发布 GitHub。

## 工作区与保护

日用源码检查点为 `codex/w1-daily-checkpoint-20261104`，原 Test 检查点为 `codex/w1-test-checkpoint-20261104`。原分支、未提交工作和运行数据保留。整合分支 `codex/w1-upstream-alpha3` 位于 `.work/self-dev/.work/alpha3-integration`；它基于日用完整源码副本，避免用落后 Test 覆盖已应用功能。两个检查点之间只有 19 个文档、CI 与声明文件差异，没有额外运行源码差异；Test 独有的发布回归入口和 build-guard 声明纳入候选，过时的图标切换说明不恢复。固定 Test 已切换到 `codex/w1-alpha3-test`，原未提交工作另存 stash，位置和恢复标识见 Test 的 .work/maintenance-20261104/source-switch-journal.json。

初始三方预检有 158 个冲突文件。源码与目录变化并不都显示为冲突：本轮还发现重复的 Markdown 导出路由、已删除的 Session inspect API、变为异步的投影注册，以及新语言字典缺失 W1 字段。不能以 Git 合并成功作为兼容验收。

## 主要取舍

| 范围 | 整合方式 | 保留的 W1 行为 |
| --- | --- | --- |
| 桌面与更新 | 接入诊断、文件拖放、窗内更新浮层和新安装器语言源 | 独立身份、免官方登录、Test 数据隔离、双确认更新、固定图标、深链与安全退出 |
| 模型与计费 | 升级 pi-ai 1.3.0，接入上游请求头贡献 | 辅助请求隔离传输、火山 effort-only、原始计费字段采集与认证/应用标识优先级 |
| MCP 目录 | 在工具声明生成处使用可释放的仅删减过滤器 | 先搜索再披露完整 schema；PTC 路径与执行权限不由披露策略改变 |
| 会话投影 | 等待注册并使用所属 handle | 完成前复核、缓存诊断、回复建议及取消/卸载时的资源释放 |
| 侧聊 | 以 SessionQuery 冷读 lease 代替已删除的 inspect | 原父会话鉴权、固定上下文快照、不为读取启动 Agent、取消后释放 |
| 菜单与复制 | 采用上游结构化菜单及统一导出解析 | 多目录/主要目录、活动列表、主侧聊选择器；可见复制仍只包含正文，完整导出保留给 API 消费者 |
| 审批与问答 | 采用上游共享卡片和已回答消息投影 | 审批不占用输入框；单选立即提交，多选集中提交；答案在步骤折叠后仍可见 |
| 网页抓取 | 采用畸形 charset 的 UTF-8 修复 | 保留显式 requirePublicIp 及严格模式解析器；Desktop 继续默认系统路由 |
| 多语言 | 吸收上游新增语言；W1 专属缺失键显式回退英文 | 中英既有文案、品牌与不显示预览标记；不使用整份英文展开来掩盖未来漏译 |

工具/菜单的重复实现只有在所有生产消费者迁移且对应行为回归覆盖后才移除。上游发布说明称独立 worktree 入口已合并，但该固定标签的源码仍将原 bundle 列为可用组件；本轮不据发布说明删除用户的启用项。桌面启动的 profile 初始化通过合成 profile 检查，保留第三方依赖、启用列表和自定义补丁。

## 验证与待办

模型相关 56 个测试文件、1,439 项通过；抓取与请求头交互的专项为 3 个文件、114 项通过，其中含重叠用例，不将各轮简单相加。升级后的 pi-ai 适配器已使用 VX Kimi K3.1 Pro 完成 low/high/max 与工具往返真实请求。桌面、工具、UI 分域回归、完整产物构建 8 项及最新产物后的 Host/Client 聚合类型检查通过。文档站点构建、5,516 个内部链接和 166 项网站测试通过；完整合并提交正常执行六项提交钩子。

W1 浏览器、Chrome 和自动审批三条无密钥会话回放通过；模型正文、工具调用与结果、权限行为和实际文件校验保持一致。SDK 计划模式回放发现 Windows 路径替换使 JSONL 无效的测试隔离缺陷，已修正路径并在子进程启动前校验回放数据。该场景最终刷新与只读回放通过，覆盖六次请求、继续规划/批准/取消及新的计划模式提示，真实 cwd、权限和模型/工具行为不变。

持久化确认记录补齐三个 W1 辅助请求事件继承的 MessageSource 元数据扩展，旧记录不被覆盖或重放；六份未冻结旧 schema 仅转换为节点表存储布局，类型图与摘要保持不变。212 项读取器测试通过，76 个持久化根和 26 条历史记录的确认关系有效。

固定 Test 已完成离线依赖更新、402 个构建输出路径的备份与替换、format 8 运行时更新和 Office 文档往返自检；开发项目的 1,593 个包均指向 Test。通过原 scripts/w1/Start-W1Test.ps1 实际启动，Host 在 46.294 秒就绪、窗口在 46.438 秒显示；旧归档因源码变化被拒绝，使用新的源码运行时。本地接口确认 14 条历史可读取、179 个启用插件 active、无 failed，实际提供的客户端脚本哈希与候选一致。W1 用量、通知、远程界面及五个核心扩展均已加载；Browser/Chrome 由 Host 直接装配，不能仅按 Loader 名称前缀判断其缺失。

日用当前启用 12 个 bundle，Test 的私有 profile 仅启用 base/web-app；日用额外的第三方和可选插件正在单独核查。已安装包的压缩门控与 Loader helper 两个真实入口检查通过，但不能据此宣称 `billion-context` 主插件与代理链全功能兼容。日用完整升级交接位于 Test 的 .work/maintenance-20261104/daily-alpha3-handoff，尚未封存为可应用状态；现有局部推广器不能处理这次完整依赖和运行时更新。

原 Test 配置和历史在用户目录 `.w1-harness-test-backups/` 下保留两份已核验备份，最近一份为 alpha3-20261104-124208，103 个文件逐项哈希一致；Electron 的 74 个文件另在 Test 的 .work/maintenance-20261104/electron-before-alpha 保留。电脑操作工具未获授权读取 W1 窗口，完整 GUI、真实浏览器/Chrome/远程设备与长期运行尚未验收；没有复制日用聊天或凭据到候选仓库。

证据入口为 `.work/self-dev/.work/maintenance-20261104/`；候选的 `.work/validation/`、`.work/desktop-integration/review.md` 及分域测试日志保存具体结果。最终状态更新[工作记录](工作记录.md)。完成 Test 后，日用推广遵守[开发流程](开发与上游维护.md#w1-self-development)；跨版本依赖与运行时更新需要独立准备，不能把普通局部构建队列当作完整升级。
