# 远程访问与 NAS 中继

最近核验：2026-10-18。本功能是 W1 本机开发版的 Android 伴随客户端，不依赖手机、电脑和 NAS 处于同一局域网。用户指定公网入口为 `https://w1hrelay.whiteone.cn:8112`，域名及反向代理由用户配置；本轮交付 NAS 可部署包，没有直接修改 NAS。

## 组成与部署

主要维护位置是 [apps/w1-remote/README.md](../apps/w1-remote/README.md)，包含端口、HTTPS/WSS 反向代理、Compose、配对、数据存储与回退。电脑端通过「应用 → 远程设备」管理连接；Android APK 沿用 Fold 图标。中继容器监听 `28981/TCP`，公网 `8112` 入口应转发到 `http://NAS内网IP:28981` 并开启 WebSocket，健康检查路径为 `/healthz`。

电脑继续使用同一 `sessionController` 和 `workspaceController`，不另起一套生产 Host，不复制会话库，不改变模型配置或插件。远程设备配置独立保存于 W1 私有主目录；远程初始化失败只影响远程功能，不阻止本机 W1 启动。服务默认关闭，开启后主动连接中继，电脑无需接受公网入站连接。

配对需要电脑确认；手机和电脑通过共享配对密钥派生连接密钥。中继只掌握路由认证与密文，不持有会话解密密钥，不保存会话。已配对手机可以查看该电脑的 W1 会话并发起当前支持的操作，首版没有按项目单独授权。更细的项目权限、手机推送、附件、远程审批仍属后续工作。

## 本轮验证

- Node 定向测试 4 项通过：加密、密文篡改/重放拒绝、地址验证、历史投影、真实 WebSocket 配对确认、持久绑定恢复、流式传输与撤销。多个断言在同一流程测试内，不计作额外测试用例。
- 真实 desktop profile 使用全新的 `.work/remote-composition-*` 目录启动，以确定性模拟模型验证项目列表、新建项目会话、消息接收、实时回复、同一 Host 历史、重复请求幂等、断线重连和停止。未读取生产历史、未发起付费模型请求。证据为 `.work/local-dev/remote-composition-result.json`。
- 桌面和 Host 完成局部类型检查与构建；原生检查发现并修复预加载扩展名错误。W1 正常退出/重开，原有项目和会话恢复；设备管理页面的最终检查记录保存在本轮工作记录。
- Android 自用 APK 构建成功，Android 15/API 35 模拟器安装、启动与扫码按钮调用原生相机权限流程通过。首轮 Gradle 构建约 1 分 37 秒，状态栏修正后的增量构建约 2 秒。没有连接实体手机，未验证实体摄像头扫描。
- 本机访问公网健康检查地址能建立 HTTPS 连接，返回 HTTP 404；尚未命中中继健康接口。这不是外网 WebSocket、移动网络或 NAS 容器验收。

## 交付与剩余验收

交付目录为 `releases/w1-remote/0.1.0/`，包含自用 APK、NAS 中继源码部署 ZIP 和校验清单。中继 ZIP 不含电脑或手机的凭据、生产会话及模型 Key。NAS 首次构建需要下载 Node 镜像和 npm 依赖；本机没有 Docker 命令，未将宿主机 Node 测试写成 NAS Docker 验收。

下一步在 NAS 启动 Compose，将公网 HTTPS 入口转发到中继，确认 `/healthz` 返回预期 JSON 和 WebSocket 可升级；随后用户手机关闭 Wi-Fi，以 4G/5G 完成首次扫码、电脑确认、续聊、后台恢复与撤销验收。手机界面当前提供原文本、工具摘要和实时文字，不包含完整 Markdown、文件产物、系统通知或远程审批。
