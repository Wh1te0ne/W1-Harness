# 远程访问与 NAS 中继

最近核验：2026-10-18。本功能是 W1 本机开发版的 Android 伴随客户端，不依赖手机、电脑和 NAS 处于同一局域网。用户指定公网入口为 `https://w1hrelay.whiteone.cn:8112`，已按用户授权在 W1-Nas 部署独立中继，修正 Lucky 中现有 W1H 规则的域名。原 DSH 与其他 NAS 服务配置未改动。

## 组成与部署

主要维护位置是 [apps/w1-remote/README.md](../apps/w1-remote/README.md)，包含端口、HTTPS/WSS 反向代理、Compose、配对、数据存储与回退。电脑端通过侧栏「手机连接」管理连接，原「应用 → 远程设备」菜单保留；Android APK 沿用 Fold 图标。中继容器监听 `28981/TCP`，公网 `8112` 入口应转发到 `http://NAS内网IP:28981` 并开启 WebSocket，健康检查路径为 `/healthz`。

电脑继续使用同一 `sessionController` 和 `workspaceController`，不另起一套生产 Host，不复制会话库，不改变模型配置或插件。远程设备配置独立保存于 W1 私有主目录；远程初始化失败只影响远程功能，不阻止本机 W1 启动。服务默认关闭，开启后主动连接中继，电脑无需接受公网入站连接。

配对需要电脑确认；手机和电脑通过共享配对密钥派生连接密钥。中继只掌握路由认证与密文，不持有会话解密密钥，不保存会话。已配对手机可以查看该电脑的 W1 会话并发起当前支持的操作，首版没有按项目单独授权。更细的项目权限、手机推送、附件、远程审批仍属后续工作。

## NAS 运行资源

核验来源为现有 fnOS 授权连接、SSH、Docker 健康状态及 HTTPS/WebSocket 实测。主机是 W1-Nas（192.168.100.55），部署目录为 `/vol2/1000/Workspace/w1h-relay/releases/0.1.1`；Compose 项目和容器名均为 `w1h-relay`，镜像为 `w1h-relay:0.1.1`，状态 healthy，重启策略 unless-stopped。服务没有数据卷或生产凭据。SSH 复用已有授权密钥，不新增账号。

Lucky 的现有「8112端口代理 → W1H Relay」子规则匹配 `w1hrelay.whiteone.cn`，后端为 `http://192.168.100.55:28981`。原误填的 .fun 已改为用户指定的 .cn，其他子规则保持原配置。容器通过默认 bridge 运行；不需要再创建 Docker 子网。程序文件在镜像里设为普通可读权限，进程仍以非 root 用户运行。

在部署目录执行 `sudo -n docker compose -p w1h-relay ps` 查看状态，`sudo -n docker compose -p w1h-relay logs --tail=50` 查看日志，`sudo -n docker compose -p w1h-relay down` 停止本项目。旧 0.1.0 包保留，但其镜像文件权限和新网络分配不适合当前 NAS，不能作为可用服务回退点；恢复当前版本使用此 0.1.1 目录执行 `up -d --build`。
