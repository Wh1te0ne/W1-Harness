# Agent Note: W1 temporary side chat

Status: implemented

English | [中文](2026-10-19-w1-side-chat.zh.md)

## Problem

Users need to ask a question while a main task runs without adding to its history, queue or draft. The existing right sidebar already owns the appropriate tab lifecycle and Start page.

## Decision

The W1 side-chat plugin registers one new guide entry and an ordinary chat tab. It freezes the main context on opening and always includes that snapshot, using an independent model route and request controller. It renders the main composer's `model.selector` Factory with side-owned state and callbacks, sharing search, grouping and advertised reasoning efforts without changing the main selection. Populated tabs require close confirmation. It creates detached memory-only Session logs containing exact requests and responses; a tab's Remote lease clears them on disconnect. It never creates or resumes an Agent and exposes no tools.

## Alternatives considered

Forking a normal Agent would introduce executable tools and durable project history. Reusing the main composer would couple drafts, Stop and queued input. A smaller model or shortened context is not selected implicitly because independence alone does not establish lower cost or adequate context.

## Consequences

Side questions cannot interrupt main execution or silently alter its context. They still consume model tokens. Tab closure and connection loss discard their history; persistence, tools and automatic merge are outside this feature. The owning [README](../../../../packages/w1/side-chat/README.md) defines behavior and verification. Synthetic host/client tests exercise snapshot isolation, multi-turn messages, cancellation, failures, lifetime and IME behavior; real-provider and native display-scale acceptance remain distinct.
